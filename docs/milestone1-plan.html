Refactor — System Check Runner Utility

Refactor

Extract a reusable shell command runner that captures non-zero exits as "fail" instead of throwing. This keeps health check logic pure, testable, and platform-agnostic across Windows, macOS, and Linux.

Files to Create
Create apps/desktop/system/runner.ts

Implementation Details

  • Export runSystemCheck(command, args?) as the primary API.
  • Return type: { ok: boolean; stdout: string; stderr: string; code: number | null }
  • Never throw on non-zero exit codes — surface them via ok: false and code.
  • Use Node.js child_process spawn with appropriate shell options per platform.
  • Cap stdout/stderr to a reasonable buffer limit to avoid memory issues.
  • Include a default timeout to prevent hanging checks.

Acceptance Criteria

  • New file exports runSystemCheck with the specified signature.
  • Returns structured result without throwing on non-zero exits.
  • Unit tests pass for success, failure, and timeout scenarios.
  • Works correctly on Windows, macOS, and Linux without platform-specific caller logic.

Risk Summary
Medium Platform-Specific Shell Behavior

System checks rely on shell commands that differ across Windows (PowerShell/CMD), macOS, and Linux. Command availability and output formats vary.

Mitigation: Centralize platform detection in runner.ts. Use simple, universal commands where possible (e.g., node --version). Test on all target platforms before marking complete.
Medium Tab Layout Regression

Wrapping existing panels in TabsContent may alter scroll behavior, padding, or nested layout contexts in subtle ways.

Mitigation: Keep panel components untouched. Use CSS containment and test scroll areas inside each tab. Verify on smaller viewports.
Low SQLite WAL Lock Contention

Health checks may write frequently during rapid re-runs. With WAL mode, reads are non-blocking, but writes are serialized from the main process.

Mitigation: Batch item inserts in a single transaction per run. Implement the cleanupOldHealthChecks routine to prevent unbounded growth.
Low Type Drift Across Processes

Adding new types to both renderer and main without a shared package can lead to desync between types.ts and electron.d.ts.

Mitigation: Define health types in apps/renderer/app/types.ts first, then mirror exactly in electron.d.ts. Run npm run typecheck after every IPC change.
High Scope Creep on Check Coverage

The list of system and runtime checks is extensive. It's tempting to keep adding more checks (e.g., cloud CLI tools, language-specific linters).

Mitigation: Stick to the defined checklist in Task 4. Mark additional checks as post-Milestone backlog. Use the skipped status liberally for edge cases.
Low Project List Badge Staleness

The project list shows a health badge that may become stale if checks are run in the background or by another workflow.

Mitigation: Derive the badge from the persisted latest run in the DB, not just in-memory state. Invalidate and re-fetch on project selection.
