Milestone 2 — Bug Recorder

Ship the complete Bug Recorder with quick capture, attachments, context snapshots, and per-project bug tracking for the DevDesk desktop app.

7 Tasks Electron + Vite + TS SQLite / better-sqlite3 React + shadcn/ui

Milestone Goal

Build and integrate the Bug Recorder as a vertical slice first: persist basic bug reports, expose them through IPC, show them in the existing Bugs tab, then layer in context capture, quick capture, attachments, search, and detail polish. The first internal target is a bug report that can be created against a project, listed, updated, persisted across app restarts, and viewed in the Bugs tab.

Context Sources

  • Recent terminal / command interactions where available.
  • Active container states from existing Docker container logic.

Result Format

  • Returns a BugContextSnapshot object matching the DB schema.
  • All JSON fields are serialized arrays/objects, not raw strings.
  • Gracefully handles missing data with empty arrays/objects instead of failures.
  • Service is pure: it returns data and does not write to the DB directly.

  • Let bugs:create optionally persist the returned snapshot when requested.

Acceptance Criteria

  • Snapshot includes run history, container state, and environment data.
  • Missing or empty sources do not cause capture failures.
  • Snapshot persistence is optional and tied to user-selected toggles.

Risk Summary
High Attachment Storage Strategy

Screenshots and logs may accumulate quickly. Storing large blobs in SQLite can bloat the DB and slow backups. Storing on disk requires path management and cleanup logic.

Mitigation: Store attachments on disk under userData/attachments/ with UUID filenames; keep only metadata and relative paths in SQLite. Implement a cleanup routine for orphaned files.
Medium Context Snapshot Size

Auto-gathering run history, logs, and container state can produce large JSON payloads. Serializing and storing this for every bug report may impact DB performance.

Mitigation: Cap history entries (last 20). Compress or truncate verbose logs. Store snapshot in a dedicated table with lazy loading in the UI.
Medium Global Modal State & Shortcuts

A global modal triggered by Ctrl+Shift+B and the Command Palette must coexist cleanly with other modals and shortcuts without focus traps or double triggers.

Mitigation: Manage modal open state centrally in App.tsx. Use a single keyboard listener and Command Palette action that both toggle the same state. Ensure only one modal is open at a time.
Medium Renderer-to-Main Context Gaps

Some context data (e.g., latest terminal commands) lives in the renderer. The snapshot service runs in the main process and may not have direct access to renderer state.

Mitigation: Pass renderer state explicitly via IPC when capturing context, or persist recent terminal history to SQLite so the main process can read it. Prefer the SQLite approach for consistency.
Low Bugs Tab Layout Regression

Replacing the placeholder Bugs tab with full panels may affect scroll behavior, padding, or nested layout contexts inside the tabbed project detail pane.

Mitigation: Keep panel components self-contained. Use CSS containment and test scroll areas inside the tab. Verify on smaller viewports.
Low Type Drift Across Processes

Adding new types to both renderer and main without a shared package can lead to desync between types.ts and electron.d.ts.

Mitigation: Define bug types in apps/renderer/app/types.ts first, then mirror exactly in electron.d.ts. Run npm run typecheck after every IPC change.
