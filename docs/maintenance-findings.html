Group 1 — Renderer crash-resilience

One unhandled rejection can wipe the entire running UI

fix/renderer-error-handling HIGH COMPLETED

Suggested commit message: “Replace DOM-destroying global error handlers with a React error boundary”. Status: completed. Runtime errors now use a React error boundary plus a non-destructive banner; renderBootstrapError is bootstrap-only and interpolated text is escaped.

F-01 Window-level error handlers overwrite the mounted React root HIGH COMPLETED

apps/renderer/main.tsx (lines 7–57)

renderBootstrapError() is wired not only to bootstrap failures but to lifetime events: window.addEventListener('error', …) and window.addEventListener('unhandledrejection', …) both call it, and it does root.innerHTML = …. Consequence: any late async rejection — a stray promise from an IPC event callback, a failed refresh, a component bug outside a boundary — destroys the whole workspace UI mid-session and replaces it with the static "DevDesk failed to render." screen. The React tree is yanked out from under the mounted root, so nothing recovers without a reload. The name says "bootstrap error" but the handler runs for the entire app lifetime.

  • Secondary issue: the error screen interpolates ${message} / ${details} into innerHTML unescaped — HTML injection from any exception text (e.g. raw git/docker stderr shown in error messages).
  • Note the code already knows some rejections are benign: isRecoverableDockerErrorMessage is swallowed silently — everything else nukes the app.

Fix direction: keep renderBootstrapError only for the pre-mount try/catch; wrap <App/> in a React error boundary; for runtime error/unhandledrejection render a non-destructive toast/banner (reuse the existing Alert components), and escape all interpolated content.

Tests to add: renderer test asserting an unhandled rejection does not unmount the app tree; error-boundary fallback renders and offers reload.

Applied: React error boundary + runtime banner; bootstrap-only fatal screen; escaped interpolation. Tests in AppErrorBoundary.test.tsx / RuntimeErrorBanner.test.tsx.

Group 2 — Command run pipeline

Stop button, unbounded output, heavy history loads, silent unresolved variables

fix/run-pipeline HIGH COMPLETED

Suggested commit message: “Harden command execution: tree-kill, bounded output, on-demand history, unresolved-variable guard”. All findings share the run-execution path (apps/desktop/ipc/registerIpc.ts → history.ts → variableResolver.ts → History UI), so they belong in one commit. Status: completed (F-02, F-03, F-04, F-05).

F-02 "Stop" kills the shell, not the process tree HIGH COMPLETED

apps/desktop/ipc/registerIpc.ts line 2251–2259 (commands:stop), spawn at line 1407 (spawn(finalCommand, { shell: true }))

Commands run through a shell; running.process.kill() kills only the shell process. On Windows the cmd.exe wrapper dies but the actual child (dev server, watcher, long build) keeps running invisibly and keeps ports/files locked; same on POSIX since no process group is used. The run is then marked stopped in history even though the process is still alive — users will see "stopped" servers that still occupy port 3000.

Fix direction: platform tree-kill — taskkill /pid <pid> /T /F on win32; spawn with detached: true and kill -pid (process group) on POSIX. Consider confirming "process still alive after stop" in history output.

Tests to add: unit test spawning a shell that launches a grandchild, assert stop terminates the grandchild (platform-guarded).

Applied: killProcessTree — taskkill /T /F on win32, process-group kill on POSIX. Test in processTree.test.ts.

F-03 Run output is buffered without limit — memory + database bloat MEDIUM COMPLETED

apps/desktop/ipc/registerIpc.ts line 1430 (running.output += text)

A command that produces heavy output (e.g. cat of a huge file, chatty dev server, npm install debug logs) grows an in-memory string without bound and then persists the entire text into run_history.output. Long-running noisy commands will bloat RAM in the main process and the SQLite file. Contrast: the engine bridge (apps/desktop/engine/binary.ts) already caps output at 8 MB — the command runner has no such guard.

Fix direction: cap the live buffer (ring buffer with head+tail, e.g. keep first 64 KB + last 512 KB, note truncation in output), cap what is written to the DB, and mark truncated runs in history.

Applied: head 64 KiB + tail 512 KiB ring buffer; truncated text persisted and returned by history:output. Tests in runOutputBuffer.test.ts.

F-04 Full run history — including every stored output — ships to the renderer at startup; no LIMIT anywhere MEDIUM COMPLETED

apps/desktop/data/store/history.ts (listRunHistory — selects output, no LIMIT); apps/desktop/data/store/bugs.ts (listBugReports — no LIMIT); consumer apps/renderer/app/App.tsx loadAll()

getRunHistory() is called on every app start and returns every row with its full output column. Combined with F-03 this can transfer hundreds of MB into the renderer over IPC on a well-used install, slowing startup and bloating the renderer heap. The output-on-demand API (history:output) already exists and is used by the viewer — the list payload simply shouldn't include outputs.

Fix direction: stop selecting output in list queries; add LIMIT/pagination to listRunHistory and listBugReports; keep getRunOutput(runId) as the single source for body text.

Applied: list payload omits output; default page 200 (max 500); History Load more; bug lists paginated. Tests in history.test.ts / HistorySection.

F-05 Unresolved non-input variables are silently executed as literal text MEDIUM COMPLETED

apps/desktop/commands/variableResolver.ts (resolve() — 'unresolved' branch returns the placeholder unchanged; only input-required is collected)

{{input.*}} variables correctly pause execution with a needs-input flow, but a typo'd or missing {{env.MISSING_VAR}}, {{project.wrongfield}} or {{container.nope}} is left as literal braces in the command and the command runs anyway (e.g. docker logs {{container.nope}}). The user gets a raw shell error for an obviously invalid command instead of a validation message.

Fix direction: collect unresolved (non-input) variables in the result and either fail prepareCommandExecution with "Unknown variable: …" or surface a confirm-with-preview warning.

Tests to add: variableResolver tests for unresolved env/project/container paths; registerIpc-level test that execution is blocked or warned.

Applied: unknown non-input tokens fail closed with Unknown variable(s): …; {{input}} still prompts. Tests in variableResolver.test.ts.

Group 3 — Platform launchers (Windows & Linux)

Linux ignores user preferences; quoting bugs in shell-true launcher strings

fix/platform-launchers MEDIUM COMPLETED

Suggested commit message: “Honor editor/terminal preferences on Linux; quote-safe launcher construction”. One logical area: apps/desktop/ipc/registerIpc.ts + apps/desktop/files/fileService.ts. Linux is a shipped, packaged platform (deb), so these are release-relevant. Status: completed (F-06, F-07, F-08).

F-06 On Linux, editor/terminal preferences are ignored entirely MEDIUM COMPLETED

apps/desktop/ipc/registerIpc.ts lines ~2094–2113 (projects:open-editor / projects:open-terminal final else branches); same pattern in apps/desktop/files/fileService.ts openFileInEditor

macOS maps MAC_EDITOR_APPS/MAC_TERMINAL_APPS, Windows maps WINDOWS_EDITOR_COMMANDS/WINDOWS_TERMINAL_COMMANDS — the Linux fallback hardcodes spawnDetached('code', …) and spawnDetached('x-terminal-emulator', …) regardless of the preference the user chose in Settings. A Linux user who selects WebStorm or gets x-terminal-emulator missing (not present on Fedora/Arch; Debian-only alternative) silently gets VS Code or a failed launch.

Fix direction: add LINUX_* command maps honoring the preference id + sensible fallbacks (gnome-terminal, konsole, x-terminal-emulator, xdg-terminal); for editors use xdg-open-style resolution or per-preference commands.

Tests to add: table-driven tests for the preference→command mapping per platform.

Applied: apps/desktop/launchers/editorTerminalCommands.ts — LINUX_EDITOR_COMMANDS (vscode/cursor/webstorm/intellij/subl) + terminal candidate chain (gnome-terminal, konsole, xfce4-terminal, x-terminal-emulator, xdg-terminal; preferred id first) tried until one launches; projects:open-editor/projects:open-terminal and the fileService.ts Linux fallback honor the preference; renderer projectsSectionConfig.ts now offers the editors plus System default/GNOME Terminal/Konsole on Linux. Tests in editorTerminalCommands.test.ts.

F-07 Shell-quoting defects in launcher command strings (breaks paths; injectable via filenames) MEDIUM COMPLETED
  • apps/desktop/ipc/registerIpc.ts resolveCustomCommand (~line 1140): {path} replaced with "${projectPath}", then run via spawn(…, { shell: true }). A project path containing ", &, % breaks out of the quoting.
  • apps/desktop/ipc/registerIpc.ts WINDOWS_TERMINAL_COMMANDS: PowerShell Set-Location -LiteralPath "${projectPath}" and cmd cd /d "${projectPath}" — double quotes don't neutralize " inside the value; PowerShell interpolates $ in double quotes.
  • apps/desktop/files/fileService.ts openFileInEditor custom-command branch (line ~369 shell: true): same interpolation with a file path. A repo can contain a file named e.g. $(calc).txt or x"&calc".txt; opening it from DevDesk with a custom editor preference executes attacker-chosen text. Low practical risk (requires custom preference + hostile repo) but it is a genuine command-injection vector and a correctness bug for legal paths containing quotes/ampersands.

Fix direction: a shared, dialect-aware quoting helper (already exists in miniature as formatPowerShellLiteral/formatCmdLiteral — reuse and extend), or drop shell:true and pass argv arrays with a raw command template where possible.

Tests to add: unit tests for the quoting helper against paths with quotes, spaces, &, %, $(), unicode.

Applied: shared dialect-aware helpers in apps/desktop/launchers/shellQuoting.ts (PowerShell/cmd/POSIX literals + buildCustomCommand); used by resolveCustomCommand, the WINDOWS_TERMINAL_COMMANDS PowerShell Set-Location -LiteralPath / cmd cd /d entries, and the fileService.ts custom-command branch. Tests in shellQuoting.test.ts.

F-08 ENOENT retry with shell: true mangles arguments containing spaces LOW COMPLETED

apps/desktop/ipc/registerIpc.ts lines 1136–1146 (spawnDetachedWithShellFallback)

The Windows fallback re-spawns the same argv array with shell: true. Node concatenates command+args without quoting in shell mode, so wt -d C:\My Projects\app becomes two broken arguments. The retry only fires after an ENOENT, which limits exposure, but when it does fire with a spaced project path the launch silently misbehaves. Related inconsistency: fileService.openFileInEditor (WSL VS Code path) spawns code without any shell fallback at all, while registerIpc does use the fallback.

Fix direction: quote args when retrying with shell (or skip the retry for argument-bearing commands); unify the fallback behavior in one shared helper used by both files.

Applied: unified spawn helpers in apps/desktop/launchers/detachedSpawn.ts used by both registerIpc.ts and fileService.ts; the win32 shell retry quotes args (quoteCmdArgIfNeeded) so spaced paths survive; the WSL VS Code path in fileService.ts now uses the fallback too. Tests in detachedSpawn.test.ts.

Group 4 — WSL embedded terminal

WSL terminals never open in the project directory

fix/wsl-terminal-cwd MEDIUM COMPLETED verify-by-hand

Suggested commit message: “Open WSL terminals in the project directory via wsl.exe --cd”. Status: implemented and unit-tested. Requires a real Windows + WSL machine for final interactive confirmation.

F-09 bash -l without --cd; POSIX path passed as a Win32 working directory MEDIUM COMPLETED

apps/desktop/terminal/terminalManager.ts lines 183–195 (create(), WSL branch)

The WSL branch spawns wsl.exe -d <distro> -e bash -l with cwd: targetLinuxPath where targetLinuxPath is a POSIX path like /home/user/proj. Two problems:

  • A POSIX path is not a valid Win32 current directory for spawning wsl.exe (node-pty/winpty → CreateProcess), so the spawn either fails outright or the cwd is ignored.
  • bash -l (login shell) starts in the user's Linux home — there is no cd and no --cd flag — so even when the spawn works, the terminal lands in ~, never in the project.

Net effect for a headline feature (WSL project support): embedded terminal is opened in the wrong directory or errors, while the external "Open in Terminal" flow (openWslProjectInTerminal) does pass --cd correctly — the two flows disagree, which strongly suggests the embedded path is a bug rather than intent.

Fix direction: spawn wsl.exe -d <distro> --cd <linuxPath> -e bash -l (wsl.exe accepts Linux paths for --cd and handles the Win32 side internally) and drop the POSIX cwd.

Tests / QA: add a manual-QA row to docs/manual-qa.md: "Embedded terminal on a WSL project opens at the project path".

Applied: the WSL PTY now invokes wsl.exe -d <distro> --cd <linuxPath> -e bash -l and no longer supplies a POSIX path as node-pty's Win32 cwd. Regression coverage in apps/desktop/terminal/terminalManager.test.ts; the dedicated packaged-app QA row is in docs/manual-qa.md. The verify-by-hand tag remains because an actual Windows + WSL terminal session cannot be authenticated by a mock.

Group 5 — Data lifecycle & export/import

Attachment-file leaks, orphaned rows, latent import corruption, swallowed export errors

fix/data-lifecycle MEDIUM COMPLETED

Suggested commit message: “Fix orphaned attachments/health rows and future-proof import column mapping”. One commit because all changes touch apps/desktop/data/store/ + deletion helpers and should ship with matching tests. Status: completed (F-10, F-11, F-12, F-13).

F-10 Attachment files leak permanently when a project is deleted or data is replaced via import MEDIUM COMPLETED

apps/desktop/data/store/projects.ts line 42 (DELETE FROM bug_reports WHERE project_id = ?); apps/desktop/data/store/export.ts replace-mode deletes; file cleanup lives only in apps/desktop/ipc/registerIpc.ts lines 2827/2917 (bugs:delete/bugs:remove-attachment)

Deleting a bug through the UI removes its attachment files from userData/attachments. But deleting a project (which cascades its bug reports) or a replace-mode import (which deletes all bug rows) leaves every referenced file on disk forever. Unbounded disk leak in userData — exactly the class of slow rot that surfaces months later as "why is DevDesk using 4 GB?".

Fix direction: before cascading deletes, collect file_path of affected attachments and run deleteAttachmentFile best-effort after the transaction (same pattern already used in bugs:delete).

Tests to add: store-level test asserting attachment rows+files are gone after project removal and after replace-import (tmp dir).

Applied: attachment paths are collected before deletion and files are removed best-effort only after a successful transaction; replace import retains paths still referenced by imported rows. Tests cover project deletion and replace import.

F-11 removeProject deletes every child table except health_check_runs LOW COMPLETED

apps/desktop/data/store/projects.ts lines 33–43

Projects, commands, chains, triggers, run history, notes, engine indexes, search sessions and bug reports are all cleaned; health_check_runs (keyed by project_id) are not, leaving orphan rows that are never shown again (the UI only queries by project id) and never cleaned by cleanupOldHealthChecks (also project-scoped).

Fix direction: add DELETE FROM health_check_runs WHERE project_id = ? to the same transaction (items cascade via FK).

Applied: project deletion now removes health-check runs; their items cascade. Regression coverage confirms unrelated project health data remains.

F-12 Import maps exported rows to columns positionally — silent corruption on future schema drift MEDIUM COMPLETED

apps/desktop/data/store/export.ts lines 279+ (getColumnNamesForExport returns allColumns.slice(0, rows[0].length); padRow maps by that prefix)

Exports store positional rows with no column names. Import assumes the export's column order equals a prefix of the current schema. This holds only while columns are strictly appended. The moment a future refactor adds a column in the middle or reorders createSchema, old backups import successfully but with silently swapped field values (e.g. name landing in type). Nothing validates; FK checks pass because values are all still valid.

Fix direction: export a header row (or object-rows) in a v2 payload while keeping backward-compatible positional reading for v1; validate row length against the stored header.

Tests to add: round-trip test simulating a mid-schema column insertion against a synthetic v1 backup.

Applied: format-v2 backups include per-table column headers; import maps values by header and validates row lengths. Existing format-v1 positional backups remain supported. Tests cover schema insertion, v1 compatibility, and invalid v2 rows.

F-13 config:export swallows the failure reason LOW COMPLETED

apps/desktop/ipc/registerIpc.ts (config:export catch block)

The catch returns { success: false, data: {…empty}, recordCounts: {} } with no error field (its sibling config:export-to-file does return one). When quick-export fails, the renderer can only show a generic failure — the actual cause (disk, permissions, DB) is lost. The unusual empty-data shape also forces the renderer to distinguish "failed" from "no data".

Fix direction: return { success: false, error: message } like the to-file variant; update the renderer type.

Applied: quick export now returns an explicit error result; the shared types distinguish successful payloads from failures, and the import/export dialog shows the returned message.

Group 6 — App lifecycle & streaming

Double instances, tray-vs-close conflict, orphaned processes/streams on quit

fix/app-lifecycle MEDIUM

Suggested commit message: “Single-instance lock, tray-aware close, quit cleanup for runs and log streams”. These interlock (close-to-tray only makes sense with single-instance + cleanup), so one commit.

F-14 No single-instance lock MEDIUM

apps/desktop/index.ts — no app.requestSingleInstanceLock() anywhere in the codebase (verified by grep)

Launching DevDesk twice starts two full app instances: two tray icons, and — more damaging — emitStartupAutomationTriggers() fires in both, so onStartup chains (deploy scripts, etc.) execute twice concurrently. Both processes also write devdesk.db; WAL tolerates it, but the in-process writeQueue serialization no longer guarantees ordering.

Fix direction: requestSingleInstanceLock(); on second-instance focus/show the existing window; quit the duplicate.

F-15 Closing the window quits the app even when the tray is enabled MEDIUM

apps/desktop/index.ts (window-all-closed → app.quit() on win/linux); apps/desktop/tray/trayManager.ts

The tray is a advertised feature (Show DevDesk, New Terminal, Run Last Command), but the moment the user closes the window on Windows, window-all-closed quits the app — the tray icon then belongs to a dying process and every tray action is useless. Users who keep DevDesk in the tray expect close-to-tray; today the setting is effectively "extra icon until you close the window".

Fix direction: when trayEnabled, intercept close → hide-to-tray (with a first-time hint); quit only via tray Quit or when tray disabled. Keep darwin behavior as-is.

F-16 Running commands and docker log streams are not cleaned up on quit LOW

apps/desktop/index.ts (before-quit closes only tray + terminals); apps/desktop/ipc/runtimeState.ts (runningCommands, runningDockerLogSubscriptions)

On quit, active command children and docker logs --follow streams are left to the OS — they keep running headless (windows: invisible orphans; next launch reconciles only the history rows via reconcileRunHistory, the processes stay). At minimum quit should be explicit about it.

Fix direction: in before-quit, tree-kill all runningCommands and kill all log subscriptions (or prompt when runs are active).

F-17 Docker log subscriptions leak on window reload/close LOW

apps/desktop/ipc/registerIpc.ts (docker:logs:subscribe, docker:logs:unsubscribe)

Subscriptions are removed only by an explicit renderer unsubscribe. A renderer reload (dev HMR or crash-recovery reload) loses the subscription id and the docker logs --follow child runs forever, broadcasting to nobody. A webContents-lifecycle hook (did-navigate/destroyed) or a generation counter on reload should reap them.

Fix direction: track subscription→webContentsId; on destroyed/did-start-navigation, kill matching streams. Also add isDestroyed() guard inside the shared broadcast() for symmetry with trayManager's guard.

Group 7 — Security hardening

Defense-in-depth gaps; no exploit chain on its own, but cheap wins

chore/security-hardening LOW

Suggested commit message: “Tighten CSP, enable sandbox, whitelist navigation, consistent trusted-IPC”. Nothing here is a confirmed vulnerability — DevDesk is local-first with contextIsolation on, no remote content, and setWindowOpenHandler denied (good). These are belt-and-braces items; grouping them keeps review easy.

F-18 CSP allows unsafe-eval/unsafe-inline for scripts in production LOW

apps/renderer/index.html (meta CSP)

script-src 'self' 'unsafe-inline' 'unsafe-eval' ships in the packaged app. A production Vite/React bundle needs neither. connect-src also allows the dev-server origins unconditionally. Tightening removes a whole class of escalation if any injection ever lands (see also F-01's innerHTML issue). Consider dev-conditional CSP or nonce-based styles for HMR in dev only.

F-19 Renderer sandbox not enabled LOW

apps/desktop/app/createWindow.ts (webPreferences)

nodeIntegration: false + contextIsolation: true are set (good), but sandbox: true is absent. The preload only uses contextBridge/ipcRenderer, which are sandbox-compatible — enabling it costs nothing and materially reduces renderer-compromise impact.

F-20 will-navigate permits any file: URL in production LOW

apps/desktop/app/createWindow.ts (navigation guard)

Production allows navigation to any file: URL. Whitelist the app's own index.html (compare resolved path) instead of the whole scheme.

F-21 Trusted-sender checks applied to only one IPC channel LOW

apps/desktop/ipc/trustedIpc.ts defines assertTrustedSender/handleTrusted (with a duplicate-registration guard), but only shell:open-external uses it; the ~70 channels in registerIpc.ts and the domain handlers register with plain ipcMain.handle.

Today there is a single trusted window and no remote content, so exposure is minimal — but the infrastructure exists and is unused; either roll it out (preferably incrementally, starting with state-mutating channels) or remove the dead abstraction. Note git:create-pr calls shell.openExternal(result.url) directly without the isSafeExternalUrl check its sibling uses (currently safe because the URL is built from a validated GitHub-HTTPS regex — keep it that way with an assertion).

Group 8 — Command vault UX gaps

Commands can't be reassigned to another project; fields can't be cleared

fix/command-edit-parity MEDIUM

Suggested commit message: “Allow editing project/working-directory and clearing fields on commands”. Backend mostly exists; this is preload + UI + semantics alignment.

F-22 A command's project and working directory are immutable after creation MEDIUM
  • apps/desktop/preload.ts — updateCommand type omits projectId/workingDirectory (main's commands:update actually accepts both).
  • apps/desktop/ipc/registerIpc.ts — even when sent, updates?.projectId ?? current.projectId and updates?.workingDirectory ?? current.workingDirectory make it impossible to clear a value (sending undefined keeps the old one).
  • apps/renderer/app/sections/CommandsSection.tsx — the edit dialog offers only name/command/description/tags.

Net: to move a command to a different project (or detach it to global) or change its working directory, the user must delete and recreate it — losing pin state and chain references. Same ?? pattern also makes description impossible to clear (F-23) — one semantics fix covers both: treat explicit null as "clear" or use has-flags.

Fix direction: extend preload + renderer types and edit dialog; adopt explicit-clear semantics; validate tags as string arrays while touching this code (tags.filter(Boolean) currently accepts non-strings).

Tests to add: registerIpc test: update with projectId: undefined clears; renderer test for the edit dialog fields.

Group 9 — Minor batch (polish & hygiene)

Small, independent items — can land as one housekeeping commit or cherry-picked

chore/maintenance-polish LOW

Suggested commit message: “Maintenance polish: stale index, terminal flush, palette shortcut, engine downgrade guard, CRLF hygiene”.

F-24 File-search index never invalidates on filesystem changes LOW

apps/desktop/files/fileService.ts (getFileIndex cache is keyed by projectId+path only)

Once built, the fuzzy-search index lives until the project is re-added or files:clearIndex is called. New/deleted files don't appear in results until then. Add mtime-based invalidation or a TTL, or refresh on section open.

F-25 Terminal loses the final output chunk on exit LOW

apps/desktop/terminal/terminalManager.ts (onExit clears the 4 ms coalescing buffer without flushing it)

clearTimeout + delete discards whatever was still buffered, so the last bytes of a dying process (often the error line!) may never reach the renderer. Flush the buffer in onExit before broadcasting terminal:exit.

F-26 Quick Launcher (Ctrl+K) is dead while any input has focus LOW

apps/renderer/app/components/CommandPalette.tsx (keydown handler skips INPUT/TEXTAREA/SELECT)

The palette refuses to open when focus is in a text field — which is most of the time while working in forms or search boxes. The guard exists so typing k in a field doesn't trigger, but Ctrl+K never conflicts with typing; drop the editable-target check for the modifier combination (keep it for plain-key shortcuts).

F-27 Engine DB schema downgrades are silently tolerated LOW

packages/engine/src/db/manager.ts (initialize() only handles version < SCHEMA_VERSION)

If a user rolls back to an older DevDesk, the engine opens a newer-schema index DB and proceeds; queries against unknown columns will fail at runtime with raw SQLite errors. Detect version > SCHEMA_VERSION and either rebuild the index or surface "index created by a newer version — please re-index after update".

F-28 Docker/WSL fallback error surface is confusing and can be slow LOW

apps/desktop/ipc/registerIpc.ts (runDockerCommand win32 daemon-error path; runWslDockerCommand per-distro retry; resolveDockerStreamLaunch)

When Docker Desktop's daemon is down on Windows, the code silently probes WSL (per-distro, each a full wsl -e bash -lc round-trip) and then reports "Docker Desktop daemon is not running. (WSL fallback also failed: …)". Latency stacks up (seconds) and the message names a product the user may not use. Consider a fast pre-flight (wsl --status) and keep the primary error verbatim in a details line.

F-29 Tray "Run Last Command" fails silently for needs-input commands LOW

apps/desktop/ipc/registerIpc.ts (runLastCommand returns {success:false,error}); apps/desktop/tray/trayManager.ts logs to console only

If the last command needs variables, the tray action reports nothing visible (error only in main-process console). Surface a renderer toast on focus, or skip needs-input entries and pick the most recent runnable one.

F-30 Synchronous fs calls on the main thread in warm paths LOW

fs.existsSync in getProjectPath/prepareCommandExecution (registerIpc.ts), statSync/copyFileSync/existsSync in attachmentService.ts, fs.existsSync in engine binary resolution.

Individually negligible; on network drives (UNC project paths are first-class here) these block the main process for seconds. Migrate to fs.promises opportunistically, prioritizing the project-path checks that run on every command execution.

F-31 PTY always uses legacy winpty (useConpty: false) LOW

apps/desktop/terminal/terminalManager.ts (both spawn branches)

ConPTY is the modern Windows console host (better resize/VT support); winpty is in maintenance mode. If the flag was a workaround for a specific issue, document it; otherwise make it platform/version-conditional.

F-32 CRLF churn warnings from the engine workspace LOW

npm run test:engine prints "LF will be replaced by CRLF" for packages/engine/src/*.ts.

Add a root .gitattributes (* text=auto eol=lf for sources or explicit per-type rules) to stop line-ending churn on Windows checkouts — cheap hygiene, prevents noisy diffs.

F-33 Post-unmount state updates in two big sections LOW

apps/renderer/app/sections/ContainersSection.tsx, HistorySection.tsx — several effects run async IPC without cancellation guards (ProjectsSection and ExportImportDialog already use cancelled flags — copy that pattern).

Harmless in React 18 (no more warning) but can surface as flicker/no-op updates when switching tabs quickly. Low-priority consistency cleanup.
