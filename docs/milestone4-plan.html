Milestone 4 — LLM Context Bundler

Enable users to export rich project context for LLM workflows by gathering files, history, health, and bugs into a structured Markdown context export.

1 Task (3 Sub-Tasks) Electron + Vite + TS SQLite / better-sqlite3 React + shadcn/ui

Milestone Goal

Build an LLM Context Bundler that gathers project files, run history, health checks, bug reports, and notes into a single structured Markdown document. Provide a polished exporter UI with section selection, live token estimation, and privacy guardrails so developers can safely paste rich context into any LLM chat or agent workflow.

Sub-Task A — Backend Bundler Completed

Implementation Details

  • Export bundleLlmContext(projectId, options?) from bundler.ts.
  • Accept projectId and optional bugReportId to focus context around a specific bug.
  • Gather project metadata: name, path, type, and detected tools.
  • Gather selected project files:
    • Respect .gitignore and exclude node_modules, .env, and secret patterns (e.g., *secret*, *key*).
    • Reuse existing engine ignore logic where possible.
    • Cap total included file size or token count; default max token limit is 100k (configurable via options).
  • Gather recent run history entries (last 20) with command, status, and timestamps.
  • Gather health check summary: latest run aggregated status + key items.
  • Gather bug reports for the project: open bugs, last 10.
  • Gather project notes: setup steps, todos, and reminders.
  • Include engine stats if available: file count, top languages.
  • Output format: Markdown with fenced code blocks for files and structured sections for history, health, bugs, and notes.
  • Include a rough token estimate using 4 chars ≈ 1 token.
  • Return type: LlmBundleResult containing markdown, tokenEstimate, includedFiles, excludedFiles, and warnings.
Sub-Task B — Renderer UI Completed

Implementation Details

  • Create LlmContextExporter as a panel or dialog accessible from the project detail view (e.g., inside the Engine tab or via a project menu action in App.tsx).
  • Show only when a project is selected.
  • Allow users to toggle which sections to include: Files, Run History, Health, Bugs, Notes, Engine Stats.
  • Display a live preview of the generated bundle in a scrollable, syntax-highlighted-like preview pane.
  • Show a live token estimate that updates as sections are toggled.
  • Provide Copy to Clipboard and Save as .md file actions.
  • Surface privacy warnings when .env or secret-pattern paths are detected and excluded.
  • Respect the max token cap: if the bundle exceeds the limit, show a clear warning and indicate which files were truncated or omitted.
Sub-Task C — Types & IPC Wiring Completed

Implementation Details

  • Add LlmBundleOptions to renderer types: sections, maxTokens, bugReportId?, includePatterns?, excludePatterns?.
  • Add LlmBundleResult to renderer types: markdown, tokenEstimate, includedFiles, excludedFiles, warnings.
  • Update apps/renderer/app/types/electron.d.ts to expose the new types on the window API.
  • Register llm:bundle-context IPC handler in registerIpc.ts that calls the bundler and returns a LlmBundleResult.
  • Expose the method in preload.ts under electronAPI.llm.bundleContext(projectId, options).
  • Wire the exporter trigger into App.tsx so it is reachable from the active project context.

Acceptance Criteria

  • llm:bundle-context IPC gathers project context into a single Markdown string.
  • File gathering respects .gitignore and excludes secrets, node_modules, and .env files.
  • Renderer UI allows section selection, live preview, copy to clipboard, and save as .md.
  • Token estimate is shown live and respects a configurable max cap (default 100k).
  • Privacy warnings are displayed when excluded sensitive paths are detected.
  • Only visible when a project is selected; works on Windows, macOS, and Linux.

Risk Summary
High Privacy Leak from .env / Secrets
Accidentally bundling .env, secret keys, or credential files could expose sensitive data to external LLM services.
Mitigation: Hard-exclude .env and common secret patterns; show clear privacy warnings in the UI; never bundle files matched by *secret* or *key* unless explicitly overridden.
High Token Count Explosion
Large projects with thousands of files or long run histories can generate massive Markdown bundles, exceeding LLM context windows and causing clipboard or renderer performance issues.
Mitigation: Enforce a configurable max token cap (default 100k); prioritize smaller, relevant files; truncate history to the last 20 entries; surface real-time token counts and truncation warnings in the UI.
Medium File Gathering Performance
Recursive file traversal on large repositories can block the main process or cause long IPC delays, degrading UX during bundle generation.
Mitigation: Reuse existing engine ignore/filter logic; cap file reads by size and count; consider yielding control during traversal or offloading to a short-lived worker if latency becomes noticeable.
Medium Cross-Platform Path Handling
Path separators and .gitignore pattern matching may behave differently on Windows vs. macOS/Linux, causing inconsistent file inclusions or exclusions.
Mitigation: Normalize paths with path.posix or path.normalize before matching; test ignore logic on Windows and Unix-like systems; reuse battle-tested ignore utilities if available.
Low Renderer Preview Performance
Rendering a large Markdown preview with thousands of lines in a React panel may cause layout thrashing or sluggish scrolling.
Mitigation: Use a virtualized scroll container or a simple monospace textarea for preview; debounce preview updates while toggling sections; cap preview length independently from the final export.
