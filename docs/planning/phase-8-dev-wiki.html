Phase 8: Dev Wiki (Enhanced Notes)

Transform the existing plain-text project notes into a rich, actionable project wiki with Markdown rendering, edit/preview toggle, runnable code blocks, and interactive task checkboxes. Covers sub-phases 8.1 through 8.4.

Objective

Give developers a first-class project wiki directly inside DevDesk. The existing plain-text notes editor works, but lacks structure, readability, and interactivity. This phase upgrades notes to full GitHub-flavored Markdown with a live preview, executable code blocks that run in the project context, and interactive task checkboxes with progress tracking—all while preserving the lightweight, local-first nature of DevDesk.

Source: Phase 8 in ROADMAP.md. This plan keeps the roadmap scope intact and expands it into implementation order, contracts, UI behavior, and acceptance criteria.

UI Behavior

Edit / Preview / Split Toggle

  • Default: Split view on wide screens (side-by-side), Edit-only on narrow.
  • Tab bar with three options: Edit, Preview, Split.
  • Edit tab renders the existing raw textarea with monospace font.
  • Preview tab renders the parsed markdown using react-markdown + remark-gfm.
  • Split view shows the editor on the left, preview on the right with a resizable divider.
  • Auto-save debounces content changes (300 ms) and calls notes:update.

Runnable Code Blocks

  • Code fences tagged with :run (e.g. ```bash:run) get a Run button in the top-right corner.
  • Clicking Run invokes commands:run-adhoc with the block content and the selected project context.
  • Output streams to the existing run history panel; a toast or inline indicator confirms execution started.
  • Blocks without :run render as standard syntax-highlighted code with a copy button only.
  • Language tag before :run (e.g. bash, sh, powershell) is passed through but does not affect execution—the default shell from preferences is always used.

Task Checkboxes & Progress

  • Markdown task list items (- [ ] / - [x]) render as clickable checkboxes in preview mode.
  • Clicking a checkbox toggles the underlying source text between [ ] and [x].
  • On toggle, the component calls notes:update-partial (or notes:update) to persist the change.
  • A progress bar at the top of the notes panel shows e.g. 3 of 7 tasks complete.
  • Progress indicator hides when zero task items exist in the content.

Risks

XSS in Markdown Rendering

Raw HTML embedded in markdown could be rendered dangerously. Ensure react-markdown is configured with allowedElements or a sanitizer plugin. Never allow arbitrary HTML passthrough from user-authored notes.

Render Performance with Large Notes

Very large markdown documents can cause re-render lag in preview mode. Mitigate by debouncing renders, virtualizing long content, or chunking the markdown AST. For Phase 8, set a practical upper bound (e.g. 50 KB) and show a warning if exceeded.

Code Block Execution Safety

Runnable code blocks execute arbitrary shell commands. The :run tag convention is an opt-in signal, but the user must understand that the block content runs verbatim. Always show the full command before execution (inline preview or confirmation dialog) and never auto-run code blocks on page load.
