Objective

Project Intelligence should give developers a fast, trustworthy read on whether a project is ready to run and what DevDesk can do next. The first release should focus on local, deterministic checks: package manager detection, dependency state, Git presence, Docker Compose presence, runtime hints, and runnable scripts.

Source: Phase 4 in ROADMAP.md. This plan keeps the roadmap scope intact and expands it into implementation order, contracts, UI behavior, and acceptance criteria.

Core Data Contract

Complete Shared report types are now defined for the main and renderer layers.

Keep the report shape small and renderer-friendly. The main process owns filesystem inspection; the renderer consumes already-normalized findings. 

interface ProjectHealthReport {
  projectId: string
  analyzedAt: string
  packageManager?: 'npm' | 'yarn' | 'pnpm' | 'pip' | 'poetry' | 'cargo' | 'go'
  hasNodeModules?: boolean
  hasLockfile?: boolean
  hasDockerCompose?: boolean
  hasGit?: boolean
  nodeVersion?: string
  availableScripts?: string[]
  missingDeps?: boolean
  status: 'healthy' | 'warning' | 'critical'
  suggestions: HealthSuggestion[]
}

interface HealthSuggestion {
  id: string
  type: 'warning' | 'info' | 'success'
  message: string
  action?: {
    label: string
    command?: string
    chainId?: string
  }
}

Inspection Rules

Check Signal Suggestion
Package manager Detect `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `requirements.txt`, `pyproject.toml`, `Cargo.toml`, or `go.mod`. Prefer commands that match the detected manager.
Missing dependencies Node project has lockfile but no `node_modules`; Python project has dependency file but no `.venv` signal. Offer install command such as `npm install`, `pnpm install`, `pip install -r requirements.txt`, or `poetry install`.
Git awareness `.git` directory exists in the project root or a parent inside the configured project boundary. Show success or info only; Git workflow features already live in Phase 6.
Docker Compose `docker-compose.yml`, `docker-compose.yaml`, or `compose.yaml` exists. Offer compose-related action once Phase 7.4 exists; otherwise show informational context.
Runtime version Read `.nvmrc`, `.node-version`, or `package.json.engines.node` for Node projects. Warn when a declared version exists but no compatible local check can be confirmed.
Runnable scripts Extract scripts and targets from supported project files. Offer one-click run buttons in the Suggested Actions panel.

UI Behavior

Suggested Actions Panel

  • Collapsed by default only when there are no warnings.
  • Shows refresh, dismiss, and run actions.
  • Displays last analyzed timestamp.

Project Card Indicator

  • Healthy: all core checks pass.
  • Warning: setup action suggested.
  • Critical: missing dependencies or inspection error.

Script Actions

  • Promote common scripts first: dev, start, build, test, lint.
  • Keep long script lists compact with a show-more control.
  • Run actions in the project root.

Acceptance Criteria

  1. Done `project:inspect(projectId)` returns a typed report for Node, Python, Rust, and Go projects without blocking the renderer.
  2. Done Missing dependency states produce clear suggestions with safe install commands.
  3. Done Detected scripts are visible and runnable from the project view.
  4. Done Project cards show a stable health indicator after inspection.
  5. Done Refresh re-runs analysis and updates the timestamp.
  6. Done Inspection errors are surfaced as non-crashing critical reports.

Risks

False Positives

Keep suggestions worded as recommendations, not guarantees. Avoid marking projects critical unless a setup blocker is clear.

Slow Scans

Read only known root files in Phase 4. Defer recursive analysis to file indexing and future intelligence improvements.

Command Safety

Suggested commands should be visible before execution and reuse the existing run-history pipeline for traceability.
